# 文档索引

这个目录只放**当前仍然成立**的文档。探索过程不进这里：定下来的写 ADR，没定下来的放 issue。

## 目录

| 路径 | 内容 | 什么时候读 |
| --- | --- | --- |
| `adr/` | 架构决策记录（Accepted），解释“为什么是现在这样” | 改动跨包边界、协议、命名约定之前 |
| `acceptance.md` | 验收门禁、浏览器阶段、fixture 说明 | 跑 `pnpm accept:glass-easel` 前 |
| `wechat-webview-parity.md` | 微信 WebView 能力对齐分与缺口 | 评估兼容性、排优先级 |
| `component-reference-diff.md` | 23 个内置组件的当前对齐状态与剩余问题 | 改内置组件 |
| `known-issues/` | 已知问题与临时处理 | 遇到相关症状时 |
| `agents/` | 给 agent 的操作手册（上下文布局、issue 流程、标签） | 开始任务前 |
| `site/` | 架构站点的页面源（Markdown），契约见 `site/CONTEXT.md` | 改站点正文时 |
| `archive/` | 历史审计与探索产物，只读，不再维护 | 考古时 |

## 写什么、放哪里

- **工程事实**（术语、边界、不变量）写进对应包的 `CONTEXT.md`，索引在根目录 `CONTEXT-MAP.md`。
- **一次性决策**写进 `docs/adr/NNNN-*.md`：一个决定一篇，Accepted 之后不改写原文，要改就新增一篇。
- **叙事与导读**（面向站点读者的长文）放 `docs/site/`，站点直接渲染这些文件；不在这里再写一份 HTML。
- **过期内容**直接删除，git 历史就是档案；只有仍被现行文档引用、且短期还要查的，才移进 `docs/archive/`。

## 维护

文档改动和代码改动走同一个 PR。不要把“计划”当成“事实”：`docs/next.md` 被删掉，正是因为它描述的路线（自研渲染框架、不对齐微信）和当前架构相反，却一直挂在根 README 上当作现行方案。
