Testing & compatibility

用真实小程序验收

Tiny 的验收不是快照测试：它编译、启动双线程、在真实浏览器里操作页面，并在失败时保存截图。

Two hosts

测试宿主与调试器，不是同一个东西

两者都基于 createStandaloneDualThreadHost，但一个服务于自动化，一个服务于人。

tests/host

无 UI 单应用测试宿主

  • Vite 提供 host / service / render 三个入口
  • 加载 tests/host/generated 的一份 manifest
  • 启动双线程，把页面挂到 #app
  • 暴露 window.__tinyRuntime 给 Playwright
  • P0 / mini / Taro 三个阶段用它
apps/devtool

带 UI 的多应用调试器

  • React 面板 + Redux 投影
  • 应用切换（demo / real）
  • 页面栈、诊断、元素树
  • Navigate / Back / Reload / Terminate
  • 独立的 debugger 验收阶段

Acceptance gate

四段浏览器流程

pnpm accept:glass-easel 会先构建并跑单测，再依次启动宿主。

阶段应用覆盖
P0 demotests/apps/demo14 步：双线程启动、组件渲染、样式作用域、checkbox/slider/switch、导航、storage、canvas 诊断、零 console error。
Existing apptests/apps/mini9 步：真实 todos、双 add-button 实例、import/include/template、输入、ECharts bar 页、子包页面、warnings。
Taro 3tests/apps/todo6 步：Redux todos 渲染、输入 + Enter 新增、勾选、筛选、Clear completed、零错误。
Debuggerapps/devtool7 步：boot、状态投影、渲染、导航/返回、应用切换、Reload/Terminate、零错误。
36 步的边界

这些步骤覆盖核心链路和真实交互，但不等于完整微信语义。API 广度、组件属性、tabBar 和页面高级事件仍需单独补齐。

Unit tests

按包拆分的 Vitest

没有全局 test runner；每个包独立运行，避免隐式耦合。

PackageTests重点
@tiny/bridge10envelope、校验、超时、批处理、MessagePort
@tiny/template-compiler28解析、ProcGen、WXS、import/include、dataset
@tiny/stylesheet-compiler24rpx、class/tag scope、host、keyframes
@tiny/cli10manifest、配置合并、脚本/样式/WXS 产物
@tiny/components6组件注册、事件归一化、AOT 模板覆盖
@tiny/runtime14API、导航、组件 schema、诊断、生命周期

pnpm accept:glass-easel

# 只跑构建 + 单测，不起浏览器
SKIP_BROWSER=1 pnpm accept:glass-easel

# 单包测试
pnpm --filter @tiny/runtime test
pnpm --filter @tiny/cli test

Taro 3

社区产物兼容不是“顺便跑跑”

tests/apps/todo 是预编译的 Taro 3 React 产物，已进入正式验收。

runtime

webpackJsonp 与页面对象

wx.webpackJsonp 作为 raw 数据属性暴露；生命周期方法挂到页面实例，支持 this.onReady.called。

template

WXS 与递归组件

外部 WXS 按带/不带扩展名注册；usingComponents 环检测避免 comp / custom-wrapper 互相引用时递归爆栈。

globals

getCurrentPages / getSystemInfo

补上 Taro runtime 依赖的全局与 callback 版系统信息；raw wx 数据属性与 unsupported API 诊断分开。

input

confirm 提交

input 组件转发 focus / blur / keydown / confirm，Taro 表单按 Enter 能提交。
