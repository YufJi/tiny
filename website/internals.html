Internals

内部分层与运行链路

从源码扫描到 manifest，再到 service / render 双线程；包边界、协议边界和样式边界都在这里。

6 core packages 1 compiler tool 1 debugger app 1 browser host

Dependency direction

依赖只向内

核心库不依赖工具/应用/测试；工具和应用只消费核心契约。

CORE @tiny/manifest artifact contract
←

packages/manifest

共享契约

只有类型，没有 compiler / runtime 逻辑。Manifest、PageArtifact、ComponentArtifact、Diagnostic 都在这里，避免 runtime 为了类型依赖 cli。

packages/runtime

消费契约

service / render 线程、glass-easel adapter、standalone host、canvas bridge、DevtoolRuntimeClient。

tools/cli

生产契约

扫描源码并生成 manifest 与线程产物；通过 library API 被测试脚本和 devtool watcher 调用。

apps/devtool

观察与控制

React 面板通过 DevtoolRuntimeClient 启动、导航、Reload、Terminate，并投影诊断与元素树。

Compiler pipeline

一次编译，产出 manifest + 线程产物

tools/cli 是唯一的产物生产者；所有宿主只读 manifest。

01 · scan

源码发现

读取 app.json，解析 pages、subPackages、usingComponents；扫描 WXML/WXSS/JS/TS/WXS 与静态资源。

02 · template

模板编译

WXML → ProcGen；处理 import / include / template / slot / wx:for / wx:if。外部 WXS 同时按带/不带扩展名注册。

03 · style

样式编译

rpx → vw；class 作用域；tag 选择器改写成 scoped marker class；生成 source map。

04 · bundle

脚本与服务入口

TS → JS，重写无扩展名 ESM specifier，esbuild 打包 service；支持 ECharts 这类 CJS/UMD 依赖。

05 · manifest

产物索引

输出 manifest.json（schemaVersion 1）、service.js、render.js、templates.js、styles 和 assets。

06 · assets

资源内联

本地图片（相对/绝对路径）在编译期内联为 data URI，静态宿主无需额外资源目录。

Threads

service 与 render 的职责边界

两个 iframe 各有 entry；host 只负责创建、握手、转发与暴露控制面。

线程入口主要职责
servicebootServiceThreadApp/Page/Component 注册、生命周期、页面栈、路由、setData、wx API、storage、animation、canvas 绘制。
renderbootRenderThreadglass-easel DOM backend、组件定义、样式注册、事件派发、元素树导出、内置组件、canvas 帧绘制。
hostcreateStandaloneDualThreadHost创建 iframe、MessageChannel 握手、BridgeConnection、页面 bootstrap、导航/API 转发。
devtoolDevtoolRuntimeClient在 host 之上提供 launch/reload/terminate、foreground/background、navigate/back、inspectTree 与状态投影。

页面生命周期

  • onLoad → onShow → onReady
  • navigateTo 隐藏当前页、创建新页
  • navigateBack 按 delta 卸载页面
  • 组件生命周期 created / attached / ready / detached
  • pageLifetimes 的 show/hide 由页面栈控制

组件模型

  • usingComponents 逐层解析，环检测避免递归注册
  • properties / data / observers / methods
  • externalClasses 与 slotted content 转发
  • 组件方法挂到实例上，支持 this.method()
  • 生命周期方法同时挂到页面实例，兼容 Taro

Bridge protocol v1

显式的跨线程契约

协议只做传输、校验、关联、超时和批处理，不定义 API 语义。

{
  protocolVersion: 1,
  messageId: "msg-...",
  kind: "call" | "reply" | "event" | "control",
  domain: "runtime" | "page" | "data" | "event"
        | "api" | "diagnostic" | "canvas",
  method: "navigate.to",
  source: "service",
  target: "host",
  payload: { ... },   // JSON-safe
  pageId?: "page-1",
  replyTo?: "msg-...",
  timestamp: 1710000000000
}

传输与批处理

MessagePort 或内存 transport；同一 page + source 的消息保序，flush 时合成 frame。

错误

ProtocolError 携带 code / message / details；超时、非法 envelope、JSON-safe 校验失败都会结构化返回。

诊断

diagnostic.log / warn / error / state 统一走 bridge，host 端归一化为 RuntimeDiagnostic，devtool 直接消费。

Styles and components

样式作用域与内置组件

style scope

class 隔离

编译期给 class 加页面/组件 scope 前缀；运行时注册顺序保证组件定义拿到 scope id。

tag marker

tag 选择器隔离

模板元素注入 wx-tag-<tag>，WXSS 的 button 改写成 .scope--wx-tag-button，不会跨页面/组件泄漏。

AOT

内置组件

18 个组件各自拥有 template.wxml + index.ts；构建期预编译为 ProcGen，运行时不解析 WXML。

canvas

离屏绘制镜像

service 侧 canvas 2D 调用被节流快照为 PNG；通过 canvas.frame 到 render 绘制到 canvas[canvas-id]。
